Comparing the sizes of the .text section in mac1.o vs mac2.o, we notice that mac2 is nearly half the size of mac1. This is attributed to the optimize option -O2 used during compilation of mac2. -O2 is the second level of optimization, used to reduce code size and improve performance at the expense of compilation time and reduced debuggability. Reading the diff of the disassembly also supports the same. -O2 removes the stack frame and directly passes the arguments to __aeabi_fmul from registers r0 and r1 instead of pushing r0 and r1 to a stack and reloading them as seen in the unoptimized mac1.

We notice that mac3 has a lot more sections (.debug_info, .debug_str, etc.) than mac1. This is attributed to the debug option -g. -g instructs gcc to produce debug info that debuggers such as gdb can use. This however doesn't change the disassembly of mac3, as the debug info is typically encoded in a binary format such as DWARF or stabs. 1H: How is the dis-assembled output of Mac4.o different from Mac2.o?

Same as above -- passing the -g option at compile creates debug sections to store debug information. gcc is unique in that it is one of the few compilers to support usage of -g with optimize options such as -O2 in this case. This allows us to debug optimized code.

26     } > SRAM2 AT> FLASH

The .init section is where things get interesting. In order for us to map functions to sections, we first need to direct gcc to assign mac_init to a new named input section .init. This can be seen in the assembly source:

add.s
55 .L3:
56     .word   acc
57     .size   mac, .-mac
58     .section    .init,"ax",%progbits
59     .align  1
60     .global mac_init
61     .syntax unified
62     .code   16
63     .thumb_func
64     .type   mac_init, %function
65 mac_init:
66     @ args = 0, pretend = 0, frame = 0
67     @ frame_needed = 1, uses_anonymous_args = 0
68     push    {r7, lr}
69     add r7, sp, #0
70     ldr r3, .L6
71     ldr r2, .L6+4
72     str r2, [r3]
73     nop
74     mov sp, r7
75     @ sp needed
76     pop {r7, pc}

The instruction .section .init,"ax",%progbits directs the assembler to create a new input section .init, set its flags (ax, allocatable and executable) and map mac_init into it. In order to achieve this, add.c is slightly modified:

add.c
1 float acc;
2 float mac(float a, float b) {
3     return acc + (a * b);
4 }
5 __attribute__((section(".init")))
6 void mac_init(void) {
7     acc = -3.1412;
8 }

Line 5 shows us the inserted directive __attribute__((section(".init"))).
