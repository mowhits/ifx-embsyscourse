What's happening here

Our add.c contains the function addf which returns the sum of two floating point numbers.

add.c 
 1 float addf(float a, float b) {
 2         return a + b;
 3 }

Starting with the compiler options used to generate the assembly files for the two target CPUs:

  1. add.sm0plus: arm-none-eabi-gcc -S -fverbose-asm -mcpu=cortex-m0plus add.c -o add.sm0plus
  2. add.sm4: arm-none-eabi-gcc -S -fverbose-asm -mcpu=cortex-m4 -mfloat-abi=hard add.c - o add.sm4
The -mcpu option is set according to the target CPU (Cortex-m0+ and Cortex-m4). The -mfloat-abi option is set to hard for the M4 and defaults to soft for the M0+. -mfloat-abi=hard directs gcc to emit instructions for the M4's on-chip floating point unit (named fpv4-sp-d16, as seen in the assembler directives) and pass floats to the FPU registers. -mfloat-abi=soft directs gcc to emit calls to floating point software emulation routines (__aeabi_fadd, in this case). These routines perform IEEE 754 operations using integer instructions for cores without FPUs, such as the M0+ in this scenario.

The diff provides a clear view of the differences in instructions due to the options chosen. For instance, the asm for M4 contains vldr and vadd, which are the FPU's load and add instructions respectively, while for M0+ the asm simply instructs the core to jump to __aeabi_fadd, the software float-add routine. The -fverbose-asm flag shows a more verbose output, detailing the various assembler directives.
